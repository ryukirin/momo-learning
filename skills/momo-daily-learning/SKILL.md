# 墨墨每日学习流程

本 Skill 依赖本地 `maimemo_*` MCP 工具。它不保存凭证、不调用 HTTP API、不直接读写 SQLite，也不修改墨墨账号。

## 分工：App 负责记，这里负责考与讲解

正式复习在墨墨 App 里完成，App 会为每个词记录当天第一次作答：`FAMILIAR`（认识）、`VAGUE`（模糊）、`FORGET`（忘记）。本 Skill **不重复 App 已经做完的检查**：

- 不逐词讲解，不让用户逐词确认「我会了」；
- 今天 App 判 `FAMILIAR` 的词一律不考（候选工具已直接排除）；其余词从整个镜像里按不熟程度挑，见下文「出题」；
- 讲解按需：用户问到哪个词就讲哪个。

## 每天的开场

1. 调用 `maimemo_get_day_state`，按 `decision` 分支：
   - `"finish-in-app"` → 今天还有到期没学的词，`unfinished.due` 列出了是哪几个。告诉用户还差几个，提醒先去 App 完成正式复习，**不得用出题代替**，也不要继续同步：没学完的词还没有作答结果，这时的快照不完整。到这里就停，等用户说学完了再从第 1 步重来；
   - `"ready"` → 今天已复习完，继续第 2 步。warnings 提到提前复习的词没做完时，顺带跟用户说一句，这不影响出题；
   - `"nothing-due"` → 今天没有待学词，工具已顺手把计划读到最新，继续第 2 步；
   - `"unknown"` → 上游没有返回进度，无法判断今天是否学完。如实告诉用户，问是否已在 App 学完；用户确认后才继续第 2 步。
2. 调用 `maimemo_sync_today_snapshot({ reason: "start_daily_todo" })` 保存当天词表。返回里的 `responseCounts` 是各作答结果的词数。这一步同时把学习记录刷新到最新，后面的候选排序依赖它；warnings 提到学习记录刷新失败时，转告用户本地记录可能落后。
3. 记下返回的 `day`（墨墨的北京时间日期）。后面日报的文件名用它，不要自己换算时区。

### 工具报错

工具出错时不抛异常，而是返回 `{ "error": { "code", "message" } }`。按 `code` 处理，不要原样重试同一个调用：

| code | 处理 |
|---|---|
| `AUTH_NOT_CONFIGURED`、`AUTH_INVALID` | 没有令牌或令牌已失效。请用户在客户端里配置墨墨令牌：DeepSeek Harness 写进凭据文件的 `MAIMEMO_TOKEN`，Claude Code 在插件设置里填写；改完重启客户端。**不得在对话里索要或接收令牌。** |
| `AUTH_FORBIDDEN` | 令牌没有所需的读取权限，请用户在墨墨开放平台检查令牌。 |
| `CREDENTIAL_STORAGE_UNAVAILABLE` | 系统凭据管理器当前不可用。请用户改在客户端里配置令牌（同上）。 |
| `UPSTREAM_RATE_LIMITED` | 告诉用户按 `retryAfterSeconds` 等多久后再试。 |
| `UPSTREAM_UNAVAILABLE`、`UPSTREAM_TIMEOUT`、`UPSTREAM_PROTOCOL_ERROR` | 墨墨暂时连不上。可以问用户是否直接用本地镜像出题，但要说明：今天的作答结果没有同步到，今天 App 已判认识的词可能被再考一遍。 |
| `LOCAL_STORE_UNAVAILABLE` | 本地数据库读写失败。把 `message` 转述给用户，停在这一步。 |
| 其他 | 把 `message` 转述给用户，停在这一步。 |

## 出题：从整个镜像取词，每天固定题量

出题范围**不是今天学的词，而是本地镜像里的整个词表**（墨墨的规划词）。今天新学的词**不进候选**：短期记忆还在，考它没有检索价值。真正值得考的是「学过一段时间、已经有点忘了」的词。今天复习时忘记或模糊的词是例外，那是 App 能给的最强信号。

取词只用一条命令：

```
maimemo_list_quiz_candidates({ limit: 20 })
```

它已经按不熟程度排好序并给了每个词的入选理由（`reason`），不要再自己拼条件：

| 优先级 | 理由 | 判据 |
|---:|---|---|
| 1 | `本地错题` | 错题本里未消除的词（`missCount` 是已累计的次数） |
| 2 | `墨墨标记顽固` | `tags` 含 `STICKING` |
| 3 | `今天复习忘记` | 今天 App 判 `FORGET` 的**复习**词 |
| 4 | `今天复习模糊` | 今天 App 判 `VAGUE` 的**复习**词 |
| 5 | `学得少` | `study_count ≤ 2` |
| 6 | `间隔较久` | 其余，且距上次学习至少 `minDaysSinceStudy` 天（默认 1） |

墨墨没有返回拼写的词没法出题，工具已经跳过并在 `skippedNoSpelling` 里计数；不要为了凑数多取候选。

工具已经做了四件事，不要绕过它：**排除今天新学的词**、**排除今天 App 判认识的词**、**要求距上次学习有间隔**（`minDaysSinceStudy`，默认 1 天；今天复习没记住的除外）、**同层里距上次学习越久越靠前**。用户想考得更早的词就调小 `minDaysSinceStudy`。

每天固定 **20 题**（用户可指定别的数量，但**单批最多 50 题**）：**不要 n 个词出 n 道题**，候选再多也只取 20 个，取多少出多少；候选不足 20 就有多少出多少，并如实说明数量。

**没考到的词不需要记账。** 墨墨自己的 SRS 会继续把它们排进之后每一天的词表，那天它们带着新的作答结果重新进入候选池。覆盖面由 App 的复习排程保证，本 Skill 不另建状态。

**只在用户要求开始当天流程或明确要题时出题，不得擅自出题。**

- 返回的 `completeness` 不是 `complete`，或 warnings 提到「尚无证明覆盖整个计划的回填」时，本地镜像只覆盖已验证范围：必须按已验证范围描述范围，不得声称覆盖全部；可以提议运行 `maimemo_backfill_study_records` 补齐。
- 候选为空时如实说明，提议调小 `minDaysSinceStudy`；不要自己编词凑数。

## 题型：只出选择题，不出对译题

**禁止**出「中文猜英语」「英语猜中文」这类词义对译题——给中文选英文词、给英文词选中文释义，都属于这类。App 已经在考这件事，再考一遍没有新信息。

下面五类是各英语考试词汇题的共同形态，**通用出题即可，不针对某一门考试做风格偏移**。全部做成四选一：

| 题型 | 题干 | 选项 |
|---|---|---|
| **语境选词** | 一个英文句子（目标词处挖空） | 4 个词：正确词 + 形近/近义干扰项 |
| **近义替换** | 一句英文，目标词用 `**粗体**` 标出 | 4 个**英文**近义词或英文释义短语 |
| **搭配填空** | 一句英文，空出搭配的一部分（如 `___ price`） | 4 个词 |
| **形近辨析** | 给出该词的**英文**释义或语境 | 4 个形近词 |
| **熟词僻义** | 一句英文，目标词用的是**生僻义项** | 4 个**英文**释义：正确项是僻义，干扰项放该词的**常见义**与其他义项 |

硬约束：

- **题干只放英文语境，不得出现中文。** 更不许写「括号里给词根 X，该填哪个形式？」这类中文指令——那等于把答案和考点一起交出去。中文一律只出现在答完之后的解析里。
- **不出「给词根选词形」这类构词题**：词根一给出来，答案就只剩机械变形，没有检索价值。
- **题干里不得出现该词的中文释义**，否则又变成对译题。
- 选项 `label` 只放词或短语本身，`description` 里**不要写释义或提示**，等于泄题。
- 选项写短：`label` 以 1–5 个词为宜。「近义替换」「熟词僻义」的英文释义压成短语（如 `in other respects`），不写整句。
- 每题 4 个选项、1 个正确答案；不用「以上都对」这类无效选项。
- **正确项的位置随机**：每题单独决定正确项放第几个，整批下来四个位置大致各占四分之一，不要连续几题放在同一位置。用户能从位置猜出答案，这题就白考了。
- 干扰项优先取 `maimemo_find_similar_words` 返回的本地计划词，不得编造不存在的词；`熟词僻义` 的干扰项取该词的常见义与其他义项。该工具没有合适候选时，改用同义或同词根角度出题，并在解析里说明依据。
- **不做需要语篇的题型**（成篇完形填空、阅读词汇题、写作）：本工具只有词表，没有语料，造出的长文质量不可控。

## 怎么问：默认一题一题，用户可指定批量

默认**一次只问一题**，每题都通过当前客户端的提问弹窗工具呈现（DeepSeek Harness 是 `ask_user_question`，Claude Code 是 `AskUserQuestion`），然后停下等用户作答。用户没有要求批量时，不得把整套题一次性写进回复。

用户明确要求“一次性出完”“批量出题”等批量模式时，以用户指定的数量和呈现方式为准。批量题目之后只说“请按题号顺序回复答案”，**不得提供任何作答示例**，也不得展示答案序列、示范选项字母或其他可能泄露答案的格式提示。只要用户回复与题号顺序的对应关系清楚，就直接判题，不要求重新格式化。

弹窗怎么填：

- `question` 放题干；`options` 放候选答案。`AskUserQuestion` 每次调用只放一道题，`multiSelect` 为 `false`。
- 需要用户自己输入的题：用 `ask_user_question` 时不给 `options`，答案会回到 `custom` 字段；`AskUserQuestion` 至少需要 2 个选项，这类题改用普通消息提问。用户在 `AskUserQuestion` 弹窗里选自带的 “Other” 并自行输入时，按输入内容判题。
- 每题给稳定的题号（`q1`、`q2`…），便于回看与统计：`ask_user_question` 放在 `id`，`AskUserQuestion` 放在 `header`。
- 若当前环境没有提问弹窗工具，默认退化为**一次一题**的普通消息提问；用户明确要求批量模式时，仍按上面的批量规则执行。

### 每题的固定顺序

每题严格按这四步走，不能跳步，也不能调换顺序：

1. **出题**：调用弹窗，只放题目，然后停下等作答。题干里不得夹带答案。**题目、答案、解析必须分离**：一次只给题目。
2. **判题并写解析**：收到答案后，先在**回复正文**里写出这一题的判定和完整解析，格式见下文「解析格式」。解析必须是用户看得到的文字，只在思考里想过不算。**答对也一样要写**，不能因为答对就直接跳到下一题。
3. **记录**：答错记错题，答对的旧错题标记消除，见「错题与日报」。
4. **出下一题**：解析写完才能弹下一题。同一轮回复里，解析正文必须出现在下一题的弹窗调用之前。两次弹窗调用之间如果没有解析正文，就是漏了。

默认写完解析直接弹下一题。用户说想先看完解析再继续时，改为写完解析就停下，等用户说「继续」再出下一题。

用户说没看到解析时，先回看自己刚才的回复。确实没写就直说漏了，按「解析格式」把漏掉的题补上；没回看之前，不要声称已经写过。

### 解析格式

**无论答对还是答错，每题解析都必须包含**下面几块，按这个顺序、用这些小标题写：

1. **判定**：题号、对错、用户选的项和正确项，如「**q2 答对**（你选 A，正确答案 A）」。
2. **题目翻译**：题目完整中文翻译。
3. **考点**：目标词或短语的中文释义（含词性），并点明本题考的是哪个义项、搭配或语法功能。
4. **选项辨析**：四个选项逐项辨析，每个选项一行，先写中文含义，再结合本题语境说明为什么对或为什么错。干扰项要说清错在哪里（义项不对、搭配不对、词性不对、形近混淆），不能只写「不符合语境」，也不能只解释正确选项或只写答案字母。
5. **一句话记住**：把考点压成一句能带走的话。
6. 答错时再加 **同义项例句**：换一个语境、用同一义项写一个完整句子，带中文翻译。

答对也要完整解析——这样才能区分“这次蒙对了”和“真的会了”。批量模式下，在用户提交整批答案后按题号逐题给出同样完整的解析。

示例（答对的语境选词题）：

> **q1 答对**（你选 address，正确答案 address）
>
> **题目翻译**：委员会将在下周的会议上处理剩下的问题。
>
> **考点**：address（及物动词），处理、着手解决。本题考的是动词义，不是常见的名词「地址」。
>
> **选项辨析**
> - redress：纠正、补救。错，对象通常是不公或失衡（redress a grievance），不是一般的待议问题。
> - address：处理、解决。正确，后面接 the remaining issues，正是「处理问题」。
> - regress：倒退、退化。错，不及物动词，后面不能直接接宾语。
> - dress：给……穿衣、装饰。错，和 address 形近，但不能接 issues。
>
> **一句话记住**：address an issue＝处理问题；redress a grievance＝纠正不公。

## 错题与日报

**只记错题，不留答题流水。** 每题写完解析就记录，不要攒到最后，这样中途中断也不会丢。

- **答错**：立刻调用一次 `maimemo_record_quiz_mistakes({ mistakes: [{ wordId, spelling, prompt, type }] })`，`prompt` 放题干，`type` 放题型。同一个词再错只累计次数，不新增记录。
- **答对**：答对的词**不写任何记录**；只有 `reason` 为 `本地错题` 的词答对时，才立刻调用 `maimemo_record_quiz_mistakes({ cleared: [wordId] })` 标记消除。
- **同一次答错只提交一次。** 这个工具每调用一次，就给 `mistakes` 里每个词的累计次数加 1，不按天去重。整批结束后**不要**把已经记过的错题再交一遍，否则次数翻倍，日报和明天的排序都会错。
- 批量模式下，用户一次交完答案：判完后调用一次，本批错题放 `mistakes`，答对的旧错题放 `cleared`。

接着生成**今日日报**，包含：

1. 本次题数与答对/答错；
2. **错词清单**：拼写、本次错在哪种题型、**错题本里累计错了几次**（用 `maimemo_list_quiz_mistakes` 读 `missCount`；一页没找全本次错词就按 `nextCursor` 翻页）；
3. **需要加强的知识点**：从错词里归纳共性——哪几个是形近混淆、哪个搭配族没记牢、哪类义项反复错；
4. 错题本当前规模（未消除 / 已消除）：直接用最后一次 `maimemo_record_quiz_mistakes` 返回的 `book`，不必另外查询。

日报是生成内容，必须标明**不是墨墨账号原文**。

**日报落盘成文件，不要只留在对话里。** 用写文件工具（DeepSeek Harness 是 `write`，Claude Code 是 `Write`）写到工作区的 `reports/` 目录，文件名 `momo-YYYY-MM-DD.md`，日期用开场记下的 `day`：

- 每天一个文件，同名文件直接覆盖——当天重做一批就以最后一批为准；
- 文件开头写日期、题数、对错数与错题本规模，正文放错词清单与「需要加强的知识点」；
- 这是**给人读的文档**，写给下一次的自己看：写得具体（哪个词、错在哪种题型、该补哪个搭配），不要写「注意加强记忆」这类空话；
- 结构化的事实（哪个词错了几次）已经在数据库里，日报不要试图代替它，只写归纳与判断。

数据库负责可查询的事实，`reports/` 负责给人读的过程记录——两者都留着，不要只留一个。

## 详解：按需触发

用户问到某个词时才讲解，不主动逐词铺开。讲解包含核心词义与词性、常见搭配、易混点或记忆提示。

**例句的触发规则**（前置条件是「该词今天不是 `FAMILIAR`」）：

| 情况 | 例句 |
|---|---|
| 该词今天 `FAMILIAR` | **不给例句**，不论单义还是多义。用户明确索要时才给。 |
| 非 `FAMILIAR`，且义项 ≥ 2（多义） | **每个义项至少一条**，一条只体现一个义项 |
| 非 `FAMILIAR`，且今天 `FORGET` | 至少一条 |

查某个词今天的作答结果：`maimemo_list_local_words({ scope: "today_snapshot", responses: ["FAMILIAR"] })`，按 `nextCursor` 翻完；不在结果里的词按非 `FAMILIAR` 处理。

例句要求：完整自然句而不是短语；该义项在句中有可辨认的语境线索；带中文翻译；不写「This is a challenge for us.」这类无信息量的万能句。

## 来源标注

墨墨开放接口只提供词 id、拼写、作答结果与学习记录，**没有释义与例句**（`/memo/interpretations`、`/memo/phrases`、`/memo/notes` 只返回账号里自己创建的内容，通常是空的），也**没有词书/考试类型接口**。因此释义、例句、题目、解析与日报全部由本 Skill 生成，必须明确标注**不是墨墨账号原文**。

## 账号写入

第一版不支持账号写入：加词、改复习状态、云词本都没有对应工具。用户提出时如实说明，并提示这些操作在 App 内完成。
